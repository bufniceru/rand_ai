# XGBoost V2 (Experimental)

Enable `xgboost_classifier_v2` in **Settings → Strategies → Relationships & Machine
Learning**. It is disabled by default and remains separate from the original
[XGBoost Classifier](xgboost-classifier.md). All predictions, comparisons,
effectiveness histories, portfolios, and exports use its displayed scores.

## Features and causal selection

V2 shares the [Lagged Logistic](lagged-logistic.md) feature snapshots. Its eight
candidates combine four lag features versus all 14 historical features, depths
1/2, and training windows 250/500. Other parameters match XGBoost V1. No class
balancing, tuning outside this grid, or early stopping is used.

Every draw supplies six positive and 43 negative candidate labels. A feature
matrix is recorded before its target arrives. State retains at most 500 completed
transitions. After 240 transitions, selection evaluates the latest 120 transitions
as three consecutive 40-draw blocks. Each block's model trains exclusively on the
retained preceding transitions, capped by its candidate window, and remains fixed
throughout that block. Consequently an inner fold can have less than 500 training
transitions even for the 500-window candidate.

Mean validation log loss chooses the configuration; exact ties favor fewer
features, shallower trees, then a smaller window. Selection repeats every 40
transitions. The selected configuration fits on completed history and refits every
ten transitions. Prediction details include training and validation log losses.

## Independent forecast evidence and fallback

Beginning with the first fitted model, V2 records its raw forecast and the
contemporaneous frequency baseline before each target arrives, even during
fallback. These later forecasts are separate from the validation folds used for
selection. Evidence persists across configuration changes because the gate
assesses the adaptive selection policy.

Every ten transitions, the latest 120 completed raw forecasts are checked. The
gate requires both a positive lower endpoint of a 95% paired moving-block
bootstrap interval for baseline-minus-model log loss and a positive mean Top-6
hit advantage. Bootstrap block length is 10, replicates 2,000, seed 20260626.
Probabilities are clipped to [1e-7, 1-1e-7] only for log-loss calculations.

Before sufficient evidence, or when either condition fails, displayed scores are
`(appearances + 24 * 6/49) / (draw_count + 24)`. Raw forecasts continue regardless.
Gate decisions persist between evaluations and can reverse. Earliest model fit
is after draw 241; earliest evidence activation is after draw 361. Rankings break
ties by ascending number. Scores remain marginal estimates, not joint ticket
probabilities. Details identify the actual score source and gate status.

## Reproducible audit and prospective evaluation

```powershell
uv run python scripts/study_xgboost_v2.py audit
uv run python scripts/study_xgboost_v2.py freeze --manifest reports/xgboost_v2/freeze.json
uv run python scripts/study_xgboost_v2.py evaluate --manifest reports/xgboost_v2/freeze.json --output reports/xgboost_v2/future
```

`audit` produces JSON diagnostics, a per-draw CSV, a Markdown report, and a freeze
manifest under `reports/xgboost_v2`. Use `--skip-controls` to omit the synthetic
learning audit, explicitly marked as not run. V1, raw V2, deployed V2, Lagged
Logistic, frequency, and uniform probabilities share identical eligible targets.
Outputs include log loss, Brier score, Top-6 distributions, three-plus rate, five
chronological blocks, paired intervals, fallback frequency, configuration choices,
and runtime. Raw-model results are never substituted for deployed-policy results.

Synthetic controls use fair, persistent-bias, and temporal-persistence 6/49 draws
generated by weighted sampling without replacement. All eight configurations are
reported for seeds 20260626/27/28, with 500 training transitions and 499 later test
transitions. Full-feature models must recover the strong fixed bias; lag-feature
models must recover persistence. Fair controls report apparent improvements and
uncertainty without demanding every random realization equal chance.

The manifest freezes candidate definitions, rules, code fingerprint, dependency
versions, and a canonical hash of the observed dataset prefix. `freeze --cutoff N`
allows a specified prefix. `evaluate` verifies the manifest, replays the frozen
adaptive policy, and scores only targets appended beyond its cutoff. It rejects
edited prefixes, changed policy/runtime, or a dataset with no appended draws.
Historical cutoffs are useful replay checks, not evidence that those draws were
unseen. To create prospective evidence, save the manifest before draws occur.

## Interpretation and operations

Repeated gate checks and selection on previously inspected history remain
exploratory. A passed gate does not prove a future advantage; a failed gate leaves
the strategy visibly using the frequency baseline. Neither behavior guarantees
predictability of fair independent lottery outcomes. Thresholds are not changed
to force activation. Dataset changes replay the full causal state; strategy cache
schema is 27. Jenkins handles portable executable packaging.
